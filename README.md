# 规划器（Todo Planner）— 初版 MVP

一个零依赖、无构建步骤的单页应用，把你提的 5 条需求全部跑通：

| # | 需求 | 实现位置 | 状态 |
|---|---|---|---|
| 1 | 输入任务，设置属性与 DDL | 任务编辑弹窗 + 属性强度三态 | ✅ |
| 2 | 按属性 / DDL 排序 | `src/sort.js`，5 种排序 + 4 种分组 | ✅ |
| 3 | 自动拆分成更小的部分 | `src/decompose.js`，LLM + 本地规则兜底 | ✅ |
| 4 | 日程表可设时段，时段带属性 | 周模板 + 时段编辑弹窗 | ✅ |
| 5 | 任务按属性填入对应时段，长任务切块 | `src/scheduler.js` | ✅ |

## 已实现的功能细节

### 1. 任务与属性

- 任务字段：标题、备注、优先级、DDL、预计耗时、单块下限/上限、状态
- 属性是**字典**（不是任务私有标签），同时挂在任务和时段上
- 属性强度三态循环（点一下切换）：**必须 require → 偏好 prefer → 排除 forbid → 关闭**
  - `require`：时段必须提供该属性才可排
  - `prefer`：有则优先，无则降级但仍可排
  - `forbid`：时段一旦带该属性则绝对不排
- 属性字典可在「管理属性」里增删，内置 6 个：深度工作 / 浅层事务 / 会议沟通 / 学习输入 / 运动 / 生活杂事

### 2. 排序与分组

核心指标是 **slack（松弛时间）= 距 DDL 的剩余分钟 − 剩余未排工时**。

- slack < 0 说明已经不可能按时完成，界面直接标红
- 排序和排程**共用同一个 slack 函数**，所以「你看到的顺序」和「系统排的先后」不会打架

排序：紧急度 / DDL / 优先级 / 预计耗时 / 创建时间
分组：不分组 / 按状态 / 按属性 / 按 DDL 紧迫度（逾期 · 24 小时内 · 7 天内 · 更晚 · 无 DDL）

### 3. 自动拆分

点任务卡片上的「拆」按钮：

- **有 LLM 配置**（设置里填 Base URL / API Key / 模型）：走结构化 JSON 输出，失败自动降级
- **无配置**：走内置规则模板，按标题关键词命中 5 类模板（写作 / 学习 / 开发 / 阅读 / 汇报）+ 1 个通用模板
- 拆出的步骤**继承父任务的 require 属性**，保证还能匹配到同类时段
- 步骤耗时之和按比例归一化到父任务估时
- 步骤数受「设置 → 最多几步」限制（默认 5）

拆分后父任务不再单独排程，只排叶子步骤，且**步骤之间保持先后顺序**。

### 4. 日程表

- 周模板：7 个星期 × 任意多个时段，每个时段有起止时间、名称、提供的属性集合
- 时段点击右上角 ✎ 可编辑，支持跨周导航
- 每个时段实时显示剩余空闲容量（`空 45m` / `已满`）
- 每天头部显示当日占用率百分比

### 5. 自动排程

点「⚡ 自动排程」，对本屏幕上显示的这周执行：

**硬约束**
- 属性 `require` 必须被时段覆盖，`forbid` 属性不得出现
- 同一时段内分片不重叠
- 单段时长 ∈ [minChunk, maxChunk]（收尾段可短于下限）
- 同一父任务的步骤按 `order` 先后执行
- 不排到「现在」之前

**软约束**
- slack 小的执行组先抢时段
- `prefer` 属性命中多的优先

**两轮策略**
1. 严格轮：不允许排到 DDL 之后
2. 放宽轮：仍排不进去的，允许超期并产生 warning

**输出**
- 周视图里出现彩色分片（颜色取自任务的 require 属性）
- 底部「排程结果」面板列出排不进的任务、还差多少分钟、以及原因（无匹配时段 / 容量已满 / 只排进去一部分）
- 每条排不进的任务旁边有「加时段」快捷入口，会预填好属性

### 6. 手动干预

- **拖拽**：从左侧任务卡片拖到任意时段，按空闲窗口自动截取长度放入
- **点分片**：选中后出现工具栏，可「锁定 / 解锁」或「删除」
- **锁定**：`locked` 的分片在重排时完全不动，其余重新计算 —— 这是避免「每次排程结果乱跳」的关键机制

## 自定义分配（v0.2）

三处可以自定义「任务怎么落到时段上」。

### 1. 任务侧：指定能/必须排进哪些时段

任务编辑弹窗里的「排程约束」区块：

- **时段 chip 三态循环**：点一下变「只能」→ 再点变「排除」→ 再点回到不限
  - 只要有任意一个「只能」，它就变成白名单：任务只会被排进这些时段
  - 「排除」是黑名单，永远不排进去
- **限定星期**：勾选周一到周日，留空表示不限
- **继承**：拆分出来的子步骤自动继承父任务的时段约束（父任务设了就以父任务为准）

不满足约束的任务不会被硬塞，而是进「排不进」列表，原因写作「被任务的时段约束挡住了」，和其他原因（无匹配时段 / 容量已满）区分开。

### 2. 时段侧：更自由的时段定义

时段编辑弹窗新增四项：

| 字段 | 作用 |
|---|---|
| 类型 | `每周重复` / `仅某一天`（选后者时按具体日期出现，只占这一天） |
| 可被占用上限（分钟） | 一个 3 小时的时段可以只允许填 90 分钟，剩下的显示为斜纹「不可用区」 |
| 最多容纳任务数 | 限制一个时段里能塞几个不同任务，超出的排不进去 |
| 拖底边改结束时间 | 在周视图里直接拖时段下边缘，按 5 分钟吸附 |

容量上限会真实影响排程：`stats.capacityMin` 统计的也是容量而不是时段全长。

### 3. 手动侧：直接拖拽改分配

周视图现在是**时间比例布局**（1 分钟 = 0.8px），所以分片的高度就是它的时长，空隙看得见。

| 操作 | 效果 |
|---|---|
| 拖任务卡片到时段 | 按剩余工时和单块上限放入一个分片 |
| **拖分片到另一个时段/另一个位置** | 保持时长平移，自动吸附到 5 分钟网格、自动夹紧在容量内 |
| **拖分片底边** | 改时长，受 `minChunk` / `maxChunk` / 容量 / 下一个分片三重夹紧 |
| **拖时段底边** | 改时段结束时间；缩短导致放不下的分片会被移出并提示 |
| 点分片 | 选中后可锁定 / 删除 |

**所有手动调整都会自动 `locked = true`**，之后再点「自动排程」时这些分片完全不动，只重算其余的。这是防止「一重排就把手工成果冲掉」的关键。

越界、重叠、超出容量、超出任务数上限都会被拒绝并 toast 具体原因，不会静默失败。

## 视图与专注计时（v0.3）

### 日 / 周 视图切换

日历面板顶部有分段控件：**日** / **周**。

**周视图**保持原样（七天并排、时间比例、拖拽调整）。

**日视图**参考 iOS 日历的日视图：
- 单列纵向时间轴，左侧小时刻度（`08:00`、`09:00`…），每小时 66px
- 时段以背景色块铺在时间轴上，左侧竖条颜色取自时段属性
- 分片是白色卡片浮在时段之上，显示任务名 + 起止时间 + 锁定标记
- 今天的当前时刻有一条红色 `now` 线
- 顶部可切换前一天 / 后一天 / 回到今天
- 时间范围自动收敛到「有内容的区间」（再对齐到整点），不会从 00:00 一直画到 24:00

同一个分片在两种视图里都能拖：**拖分片改时间、拖底边改时长**。

两种视图的像素比例不同（周 0.8px/分钟、日 1.1px/分钟），所以拖拽换算不写死常量，
而是用「时段元素高度 ÷ 时段时长」现算，再加一个 `grabMin` 记住「抓住的是分片内第几分钟」，
保证卡片不会跳到指针下面。

页面状态一变就整体重绘，滚动容器会跟着重建。所以重绘前会记下各滚动容器
（任务列表 / 日视图 / 周视图横向）和整页的滚动位置，画完再放回去——
拖完分片、弹完 toast 都不会把视角弹回顶部。

拖拽结束时浏览器会补发一次 click，需要吞掉；但抑制只在这一轮事件循环内有效
（`setTimeout(0)` 解除），否则你拖完之后下一次正常点击也会被吃掉。

### 专注计时

每个分片右上角有 **⏱** 按钮（分片太矮时自动隐藏，避免误触）。点一下立刻开始计时并弹出番茄钟面板：

- **圆环进度**：SVG 描边，随倒计时收缩
- **倒计时**：`mm:ss`，分钟可以超过 59（90 分钟会显示 `90:00`）
- **暂停 / 继续 / 重置 / 结束并记录**
- **目标时长可改**：默认取分片时长，中途可以调整，但不会低于已专注的时长
- **收起不中断**：关掉面板后变成右下角悬浮计时条，可以继续操作日程，点它再展开
- **结束时落库**：写入 `focusSessions`（任务、分片、计划分钟、实际分钟、状态、结束时间）；不足 1 分钟不留记录

计时不靠「每秒减一」，而是 `elapsed = accumulated + (running ? now - startedAt : 0)`：
切后台、锁屏、刷新回来都不会走偏，`elapsed` 也如实记录（超时了就是超时了，不会被夹回计划值）。


### 专注时长回写日程

专注结束后，分片时长会按**实际专注分钟数**改写（可在设置里关掉）：

| 情况 | 结果 |
|---|---|
| 计划 60，实际专注 25 | 分片缩短到 25 分钟，原计划值存进 `plannedMin` |
| 计划 60，实际专注 90，后面有空 | 分片延长到 90 分钟 |
| 后面紧跟着别的分片 | 延长到「下一个分片开始」为止，并提示实际专注了多少 |
| 超出时段容量上限 | 延长到容量边界为止，并提示 |
| 实际不足 1 分钟 | 不记录、不回写 |

回写后的分片：

- `actualMin` 记录真实专注分钟（即使被夹紧也如实保存）
- `plannedMin` 保存第一次回写前的原时长
- 自动 `locked = true`——这是既成事实，再点「自动排程」不会被冲掉
- 周视图时间行显示 `· 实25m`，日视图显示 `· 实 25 分钟`

**可撤销**：选中该分片，工具栏里会多出「还原计划时长」，一键把分片改回原计划（若时段已被改短，按可用上限还原并提示）。

设置里可以整体关闭：关掉后专注只写 `focusSessions` 记录，不动日程。

## 部署到 GitHub Pages

这个站是纯静态的（无构建步骤、无后端），把仓库推上去就能跑。

```bash
cd todo-planner
git init -b main
git add .
git commit -m "feat: 规划器"

# 在 GitHub 上新建空仓库（不要勾 README/gitignore），然后：
git remote add origin https://github.com/<你的用户名>/<仓库名>.git
git push -u origin main
```

然后在仓库里开启 Pages，两种方式二选一：

| 方式 | 操作 | 适合 |
|---|---|---|
| **A. 分支直发**（最省事） | Settings → Pages → Source 选 `Deploy from a branch` → Branch `main` + `/ (root)` → Save | 想三分钟搞定 |
| **B. Actions**（推荐） | Settings → Pages → Source 选 `GitHub Actions`；仓库已带 `.github/workflows/pages.yml`，push 后自动发布，并会先跑一遍单元测试 | 想加质量门禁 |

约 1 分钟后访问：

```
https://<你的用户名>.github.io/<仓库名>/
```

### 已经在仓库里准备好的东西

- `.nojekyll` —— 关掉 Jekyll，避免它忽略某些以下划线开头的文件
- `.gitignore` —— 排除 `node_modules/`、`.DS_Store`、日志
- `.github/workflows/pages.yml` —— 测试通过后自动发布
- **全站相对路径** —— `./src/app.js`、`./styles.css`，所以挂在 `/<仓库名>/` 子路径下不会 404

### 几个坑

- **仓库名取 `<用户名>.github.io`** 时，站点挂在根路径 `https://<用户名>.github.io/`，其余仓库名都挂在子路径下。两种都支持。
- 千万不要把资源改成 `/src/app.js` 这种**绝对路径**，子路径部署会直接白屏。
- 第一次发布有 1～2 分钟延迟；页面没更新先看 Actions 或强制刷新（缓存）。
- 数据存在浏览器 `localStorage`，按域名隔离。换仓库名、换自定义域名，都等于换了一个新站点，旧数据不会跟过去。
- 想绑自己的域名：Settings → Pages → Custom domain，并在 DNS 加一条 CNAME。

### 和 easy-vibe 那种站不是一回事

[easy-vibe](https://datawhalechina.github.io/easy-vibe/en/) 是 **VitePress 文档站**（`/en/`、`/zh-cn/` 是多语言 locale 路由，资源带 hash）。本项目是**单页应用**，不需要也没法直接用 VitePress 的结构。

如果你想要「文档 + 应用」合体（比如首页是介绍页、`/app/` 才是规划器，配多语言），那需要另外搭一层 VitePress，把当前应用原样放进 `public/app/` 或独立子目录，再用 locale 路由分流。

## 跨周排程（v0.4）

**自动排程不再局限在「当前这一屏 7 天」**，可以按设定的跨度往后铺，长时间任务会自然摊到多周。

### 怎么用

顶栏按钮会显示当前跨度（`⚡ 排程 14 天`）。改跨度：**设置 → 自动排程跨度**：

| 选项 | 含义 |
|---|---|
| 本周 7 天（不跨周） | 老行为，只看这一周 |
| 未来 14 天（跨 2 周） | 默认值 |
| 未来 21 / 30 / 60 天 | 长期任务、论文、备考这类场景 |

### 行为细节

- **起点固定是「今天所在周的周一」**，不受你当前浏览到哪一周影响。
  这样你在翻看下个月时点排程，也不会把计划排到过去。
- **长任务自动跨周切块**：一个 10 小时的任务、单块上限 120 分钟，会切成 5 段，
  按时间顺序铺到未来几个周一/时段里，而不是挤在一周内或直接判定「排不进」。
- **清理范围按日期算**，不按「有没有时段」算。跨度内某天没排时段，那天的旧分片也会被清掉，
  不会留下幽灵数据。
- **跨度外的分片完全不动**：你昨天排的 60 天后的内容，不会因为今天重排 7 天就消失。
- 结果面板会显示 `11/17–11/30（14 天）· 容量 … · 已排到 11/24`，
  一眼能看出计划铺到了哪天。

### 实测效果（内置演示数据）

| 跨度 | 排入分片 | 排不进 | 计划覆盖到 |
|---|---|---|---|
| 7 天 | 7 | 1 | 11/20 |
| 14 天 | 8 | 1 | 11/24 |
| 30 天 | 9 | 0 | 12/01 |

## 已知边界（初版刻意没做）

| 缺口 | 说明 |
|---|---|
| 例外日 | 支持「仅某一天」的单次时段，但没有批量例外日（节假日整体停用） |
| 估时校准 | 已能把实际时长回写到分片，但还没用历史数据反推校准 `estMin` |
| 依赖跨任务 | 只支持同父步骤的顺序依赖，没有任务间的任意 DAG |
| 算法最优性 | 纯贪心，不做回溯/局部搜索；规模大了质量会下降 |
| 同步与多端 | 只有 localStorage，没有账号和后端 |
| LLM 拆分稳定性 | 无 API Key 时用规则模板，拆分质量受限于模板覆盖度 |

## 后续可加的三件事（按性价比排序）
